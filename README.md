# At Stake

A prediction market on one bit: **did these Bitcoin coins enter a Stacks
protocol bond before burn height H, or did they stay idle?**

Chips are sBTC. The subject is native L1 BTC. Settlement reads Bitcoin.
There is no admin key and no oracle principal.

## Status

58 tests green on Clarity 6 / Epoch 4.0.

```
npm install     # needs npm >= 11, see Toolchain
npm test
```

### Proven
- Complete-set escrow: 1 sat of sBTC mints 1 IDLE + 1 BONDED share; the pair
  merges back to 1 sat any time before resolve, so the two prices sum to 1.
- `vault == idle-circ == bonded-circ` holds across every mint and merge.
- Contract solvency: it never pays out more sBTC than it holds.
- Status is settable by exactly two functions. No admin path exists.
- A Clarity SPV merkle verifier that matches real Bitcoin tree math at every
  index, handles the odd-node duplication rule, works at 12-deep proofs, and
  rejects both a forged transaction and a real one at a wrong index.

- Share transfer, so someone can sell the side they do not believe. Circulating
  supply is unchanged by a transfer, and the vault invariant survives it.
- A Bitcoin transaction parser: compact-size varints, output value and
  scriptPubKey extraction, and detection that a transaction spends a given
  outpoint. Checked against an independent serializer, not the same code path.

- `create-market`: commits a snapshot UTXO by proving on chain that the
  outpoint is confirmed on Bitcoin, pays this market's scriptPubKey, and clears
  1 BTC. The cutoff lives in the contract, not the domain name.
- `resolve-bonded`: the full YES claim, six checks in one call.

### The six checks in `resolve-bonded`

1. Market is open and inside the window.
2. The lockup transaction is really in a Bitcoin block (SPV).
3. It spends coins this market committed to at create time. **This is the step
   pox-5 does not do**, and the only reason a market can be about a Bitcoin
   wallet at all.
4. The coins landed in a P2WSH whose witness script embeds
   `sha256d(to-consensus-buff?(staker))`, above the threshold.
5. pox-5 agrees that staker holds a live bond at this bond-index.
6. `is-l1-lock` is true. sBTC bonds resolve NO; v1 is native L1 only.

Each has a test that it rejects the corresponding forgery: a fake merkle path,
an unrelated transaction, a lookalike P2WSH bound to a different staker, a
witness script one byte off, an sBTC bond, a wrong bond-index, an
under-threshold amount, and a staker with no membership.

### Testing against real pox-5

`contracts/pox5-sim.clar` is the **real** PoX-5 contract, generated by
`build-pox5-sim.sh` from the pristine testnet source in
`vendor/pox-5.testnet.clar`. It is deployed under our own deployer so that we
hold `bond-admin` and can drive the true bond lifecycle in simnet:

```
grant-signer-key   real secp256k1 grant, verified on chain
register-signer    ST1PQHQ....test-signer-manager
setup-bond         as bond-admin, with an allowlist
register-for-bond  writes a real protocol-bond-memberships row
```

Only three lines differ from the deployed contract, all forced by simnet: the
sBTC id (clarinet auto-funds exactly one), `bond-admin` (so we are the admin),
and the single burn-header assert. The merkle proof under it still runs for
real, as does every cycle, allowlist, rollover and custody rule.

`contracts/test-signer-manager.clar` is the `signer-manager-trait`
implementation `register-for-bond` demands.

## The one thing simnet still cannot do

There are no mocks left. `resolve.test.js` drives real pox-5 end to end. The
single remaining substitution is the burn-header check, and it exists because:

The only writer of `protocol-bond-memberships` in real pox-5 is
`register-for-bond`, which runs `verify-l1-lockups` -> `verify-block-header`:

```clarity
(match (get-burn-block-info? header-hash expected-block-height)
    bhh (is-eq bhh (reverse-buff32 (sha256 (sha256 headerbuff))))
    false
```

That is the same check `tx-was-mined` does here, and it fails in simnet for the
same reason `SIM-SKIP-HEADER` exists: simnet serves synthetic burn blocks that
no real Bitcoin header hashes to. Registration is also allowlist-gated by the
bond admin and moves real sBTC through `roll-sbtc`.

`build-pox5-sim.sh` bypasses exactly that assert and nothing else, so every
other rule -- the lockup script template, amounts, unlock heights, duplicate
outpoints, allowlists, cycles, rollover, sBTC custody -- is enforced for real.
The merkle proof underneath it is verified genuinely.

## Two things the simnet cannot prove

- **Header binding.** `get-burn-block-info?` returns simnet's synthetic burn
  blocks, so `build-sim.sh` compiles a `SIM-SKIP-HEADER` constant that bypasses
  the three-line check that the supplied 80 bytes hash to the burn block the
  chain already agreed on. Everything downstream of it is tested. That check
  itself only runs for real on testnet.
- ~~**The exact lockup script template.**~~ Pinned. `tests/template.test.js`
  checks `btc-parse` against pox-5's real `construct-lockup-script` /
  `construct-lockup-output-script`, byte for byte. The commitment sits at
  offset 13: `1` OP_IF + `4` CLTV scriptnum + `2` `0xb167` + `6`
  `0x82012088a820`. A template change upstream now breaks a test.

## Cost: the open question is closed

Measured on simnet with `npx vitest run -- --costs`, against a 5,000,000,000
runtime block limit:

| operation | runtime | share of a block |
|---|---|---|
| 12-deep merkle proof | 44,557 | 0.0009% |
| `tx-spends-outpoint`, 10 inputs, 1,920-byte tx | 828,466 | 0.0166% |
| `get-output`, 10 outputs | 1,205,416 | 0.0241% |

A full `resolve-bonded` is roughly 2.1M runtime, about **0.042% of a block**.
Around 2,400 settlements would fit in a single block.

So the fully on-chain resolver is affordable and no challenge-window fallback
is needed. Settling costs an ordinary Stacks fee, not a prohibitive one, which
means a small holder can afford to settle their own market.

## Toolchain

Clarinet moved from `hirosystems` to `stx-labs`; the npm package is
`@stacks/clarinet-sdk` (3.23.x). `@hirosystems/clarinet-sdk` is stale at 3.8.1
and only reaches Clarity 4 / Epoch 3.3.

This project targets **Clarity 6 / Epoch 4.0**, which is what pox-5 needs.

**`npm install` requires npm 11 or newer.** npm 10.9.0 crashes resolving this
tree with `Cannot read properties of null (reading 'edgesOut')`, an arborist
bug. `--legacy-peer-deps` silences it but installs an unsupported combination;
do not use it. If your npm is older: `npx npm@11 install`.

vitest is pinned to **4.x** on purpose. `vitest-environment-clarinet@3.0.2`
declares a peer range topping out at `^4.0.0`, so vitest 5 is not yet usable
here.

Clarity 4 overhauled `as-contract`. Asset movements out of the contract now
require explicit allowances:

```clarity
(as-contract?
  ((with-ft 'SM3...sbtc-token "sbtc-token" payout))
  (try! (contract-call? 'SM3...sbtc-token transfer payout current-contract who none)))
```

If the callee moves anything beyond the allowance the whole call rolls back.
Note `current-contract`, which replaces `(as-contract tx-sender)`.

### The bug mainnet caught

The first mainnet `create-market` aborted with `ERR_BAD_HEADER`.
`get-burn-block-info?` returns the burn block hash in display order while
`sha256d(header)` is internal order, so the comparison could never succeed on a
real Bitcoin block -- the contract was inert. pox-5 does the same reversal in
its own `verify-block-header`.

All 58 simnet tests passed throughout, because `SIM-SKIP-HEADER` bypasses
exactly that assert. Header binding was listed as an untested gap; it was
untested *and* wrong. Cost to find: one transaction.
